# April 16, 2026 - LeadGen Audit Stability & UI Enhancements

## Motivation

Several legitimate business websites were incorrectly failing our local SEO audits and being skipped. This occurred because our fast async HTTP client (`aiohttp`) was occasionally aggressively timing out or failing on slower, aggressively cached, or generic shared hosting servers (such as GoDaddy shared IPs), causing valid leads to be flagged as `UNREACHABLE` or `PARKED`.

To resolve this, we needed to make the network request engine significantly more resilient, and we needed to expose a way for users to visibly interact with and re-run audits for these skipped sites easily from the frontend dashboard.

## Summary of Changes

### 1. Hardened Site Classification Engine (`site_checker.py`)
- **Timeout Relaxation:** Increased standard `aiohttp` timeouts from (25s/10s) to (45s/15s) to properly accommodate slower-loading or unoptimized business websites across slow networks.
- **Synchronous `requests` Fallback Integration:** Architected a failover mechanism where if `aiohttp` throws `TimeoutError`, `ClientConnectorError`, or connection-refused errors, the engine seamlessly hands off the request to the more resilient `requests` library in a background thread (`run_in_executor`). 
- **Graceful SSL Fallback:** Introduced an automated `http://` retry mechanism for sites that fail to connect via `https://` due to expired or misconfigured SSL certificates.
- **Regex Syntax Stabilization:** Fixed edge cases parsing navigation parameters and rectified a Python `SyntaxError` that broke `uvicorn` restarting by utilizing clean quote escaping on `class="..."` and `href="..."` string validations.

### 2. Backend Engine Scalability (`leads.py`, `audits.py`, `schemas.py`)
- **`GET /audits/stats` Counting Updates:** Implemented programmatic aggregation on the database layer to count rows where `Audit.error_message LIKE "SITE_STATUS:%"` so we can securely display "Skipped" totals dynamically. 
- **Targeted Endpoint (`POST /audits/trigger-skipped`):** Introduced a specialized trigger route that natively grabs exclusively skipped records from the `Audit` persistence layer, clears their error message states back to `None`, resets to `pending`, and kicks off an asynchronous batch re-audit routine.
- **Filter Query Engine Expansion:** Updated `GET /leads` behavior to support the `?status=skipped` parameter natively securely mapping to joined `Audit` columns.
- **Pydantic Model Updates:** Utilized `@computed_field` in `LeadResponse` architecture from Pydantic V2 to selectively render the `audit.error_message` variable inline during REST API Serialization, eliminating the need to over-fetch nested audit items. 

### 3. Frontend Reporting Application (`Leads.jsx`, `client.js`)
- **Interactive Re-Audit Modalities:** Updated the "Audit All" launch modal to inject an orange "⚠️ Re-audit Skipped" card automatically displaying the exact number of sites currently stuck.
- **Advanced State Filtering:** Pushed a new dropdown configuration array to the UI allowing you to specifically toggle and render solely "Skipped (Errors)".
- **Table Data Transparency:** Intersected table row displays to detect custom backend `audit_error` variables natively injected off the payload. We extract the exact explicit failure tag (e.g., `UNREACHABLE`, `PARKED`) and map it as a bold indicator badge exactly where standard success status icons go.
