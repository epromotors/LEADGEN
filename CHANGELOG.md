## Latest v5.1.0 — Outreach Design Redesign, Inbox Email 2 Modal, Port Migration & Reset Utilities (September–October 2026)

### Overview

LeadGen OS v5.1.0 brings a complete aesthetic and structural redesign to the initial outreach email (Email 1), introduces a live Email 2 Compose & Preview modal directly inside the Converted Leads Inbox, migrates development server ports to avoid collisions (FastAPI backend :8001, Vite frontend :5174), implements a dedicated test email API endpoint with standalone test scripts, and adds a full database reset utility (`reset_leads_to_fresh.py`) along with global lead datasets.

### 1. Branded Email 1 Visual & Architectural Redesign (`outreach_engine.py`)

Completely overhauled `build_html_email(lead, audit)` in `backend/app/engines/outreach_engine.py` (and preview in `backend/email_preview.html`, based on `email-website-design1-redesigned.html`):
- **Card-Based Visual Frame:** 600px width responsive email card container with `#0d1b2a` dark navy header, crisp 14px rounded corners, and soft `#eff4ff` tinted content background.
- **Official Branding Banner:** High-resolution TEB Solutions / Tattavit logo banner (`LOGO_URL`) with a sleek "Web Design & Digital" right-aligned badge.
- **Service Offering Pill:** High-contrast pill badge highlighting primary competencies: `Website Design • Redesign • Technical Review`.
- **Dynamic Observation Headline:** Dynamic H1 headline personalized with the lead's domain: *"Observations on {domain}'s website structure & experience"*.
- **Domain & Industry Personalization:** Narrative copy acknowledging the lead's specific domain and sector, positioning TEB Solutions as a trusted design partner.
- **4 Key Usability Pillars Card:** Embedded white card detailing foundational website factors:
  - *Modern First Impression:* Clear services and credentials immediately upon landing.
  - *Mobile Responsiveness:* Seamless readability and effortless navigation on small screens.
  - *Direct Contact Pathways:* Intuitive, visible enquiry access across all pages.
  - *Technical Foundations:* Clean page indexing, XML sitemap configuration, and reliable load performance.
- **Direct Portfolio Proof Strip:** Live client website showcase built and managed by TEB Solutions:
  - **Hexaprime.me** — Branding & Web
  - **Channelnexus.me** — SaaS Landing
  - **Sketchlife.ae** — UAE Lifestyle
  - Accompanied by credibility note: *"+ many more white-label solutions across UAE, India & the UK."*
- **2x2 Quick Evaluation Grid:** Structured dashed review callouts covering First Impression, Mobile Experience, Visitor Contact Flow, and Google Basics.
- **Low-Friction Informational Closing:** Thoughtful closing note removing aggressive sales pressure:
  > *"These observations are shared purely as helpful context for your team's website planning. There is no need to reply or follow up."*
  This low-pressure framing significantly builds trust and improves natural response rates.
- **Branded Navy Footer:** Dark footer matching header styling, carrying official contacts (`tebsolutions.in`, `info@tebsolutions.in`) and a courteous disregard notice.
- **Curiosity-Gap Spintax Subjects:** Refined subject line templates to avoid spam filters while maintaining curiosity:
  `{a note about {domain}|an idea for {domain}|website observation: {domain}|regarding {domain}}`
- **Hostinger Daily Send Cap & Account Rotation:** Integrated automatic sender rotation with strict 1,000 sends/day enforcement per Hostinger account. If all configured accounts reach daily capacity, campaigns pause cleanly and safely.
- **Offline HTML Preview Generator:** Created `backend/gen_preview.py` which mocks SQLAlchemy and renders `build_html_email` into static `email_preview.html` for instant visual inspection.

### 2. Converted Leads Inbox — Email 2 Compose & Preview Modal (`Inbox.jsx`, `replies.py`)

Added a comprehensive follow-up workflow for positive replies inside `frontend/src/pages/Inbox.jsx`:
- **Dual-Mode Compose & Preview Modal:**
  - **Live Preview Tab:** Displays rendered HTML proposal generated by `GET /api/replies/preview-email2/{lead_id}` (utilizing `build_html_email_full`).
  - **HTML & Subject Editor Tab:** Allows operators to customize the HTML body or edit the subject line before sending.
- **One-Click Send Action:** Integrated `POST /api/replies/send-email2/{lead_id}` with confirmation prompt, loading indicators, and error feedback.
- **PDF Attachment Support:** Automatically attaches the lead's generated PDF audit report (if available in `audits.pdf_path`) to Email 2.
- **Activity Logging:** Records `email2_sent` events with sender account, recipient email, and business name in `activity_log`.
- **False-Positive Reclassification:** Added `PATCH /api/replies/reclassify/{lead_id}` to revert false-positive auto-replies from `converted` back to `emailed` status (`reply_type = 'other'`) without deleting the lead.
- **Dynamic Sidebar Badge:** `Layout.jsx` displays real-time green badge count for converted leads powered by `GET /api/replies/stats`.

### 3. Network Architecture & Development Ports Migration

Resolved port conflicts and updated dev tooling:
- **Backend Port Moved to 8001:** `backend/run.py` updated to run Uvicorn on port `8001` (`host="0.0.0.0", port=8001, reload=True`).
- **Frontend Vite Port Moved to 5174:** `frontend/vite.config.js` configured with `server: { port: 5174, proxy: { '/api': { target: 'http://localhost:8001' } } }`.
- **CORS & App Settings Synchronization:**
  - `backend/app/config.py`: `FRONTEND_URL = "http://localhost:5174"`
  - `backend/app/main.py`: CORS `allow_origins` includes `"http://localhost:5174"` alongside existing ports.
- **Launcher Automation (`START.bat`):** Updated one-click batch launcher to start FastAPI on `:8001`, Vite on `:5174`, wait 6 seconds, and open `http://localhost:5174` in the browser automatically.

### 4. Direct Campaign Test Email API & Standalone Test Tooling

- **Router Endpoint `POST /api/campaigns/send-test`:**
  - Accepts `to_email` and `lead_id` in request body.
  - Automatically loads the lead and its audit status, resolving either the live-site proposal (`build_html_email`) or the no-site pitch (`build_no_site_email`).
  - Sends a `[TEST]` prefixed email immediately using the first configured SMTP account.
  - Returns confirmation with lead name, template used, subject, and sender account.
- **CLI Test Scripts (`send_test_email.py` & `backend/send_test_email.py`):**
  - Standalone scripts allowing rapid template verification from the terminal.
  - Includes Windows `asyncio.WindowsSelectorEventLoopPolicy` configuration to prevent Windows socket crashes.

### 5. Lead Reset Utility & Global Dataset

- **`backend/reset_leads_to_fresh.py`:**
  - Safely clears email and reply tracking (`last_emailed_at = None`, `replied_at = None`, `reply_snippet = None`, `reply_type = None`) across all leads.
  - Automatically sweeps stale audits stuck in `running` state (>30 minutes old) and transitions them to `failed`.
  - Sets `lead.status = 'audited'` strictly for leads where `audit.status == 'done'`, and `lead.status = 'new'` otherwise (satisfying Guardrail #27).
  - Resets active or paused campaigns back to clean `draft` state with zeroed send/skip/fail counters.
- **Global Leads Datasets:** Integrated `leads/global_leads.xlsx` and `leads/global_leads.csv` for expanded prospecting.

## Latest v4.5.0 — UI/UX Audit Axis (May 9, 2026)

### Overview

Added a dedicated **UI/UX Audit Axis** to the LeadGen OS audit engine. The system now analyses 8 user-experience factors on every audited website, stores results in 9 new database columns, displays a 6-axis performance ring in the Audits dashboard, appends a UI/UX section to every PDF report, and weights UX at 15% of the total audit score.

### 1. `auditor/ux.py` — New UX Module

New file `auditor/auditor/auditor/ux.py` implements 8 UX check functions:

| Function | What it detects |
|---|---|
| `audit_cta()` | Detects primary CTA button (Get Quote, Book Now, Contact Us, etc.) |
| `audit_cta_above_fold()` | Checks if CTA appears in first 1/3 of visible page area |
| `audit_hero_headline()` | Checks for a clear H1 value-proposition headline |
| `audit_font_size()` | Scans CSS/style attributes for body font-size ≥ 14px |
| `audit_contrast()` | Detects low-contrast text patterns (white-on-light, black-on-dark) |
| `audit_nav_links()` | Counts `<nav>` or header link elements |
| `audit_cookie_notice()` | Detects cookie/GDPR consent banners |
| `audit_live_chat()` | Detects Tawk.to, Intercom, Tidio, WhatsApp, Crisp widgets |

## v4.3.1 — Data Sanitization & Normalization (April 22, 2026)

### Overview

Introduced automated URL and Business Name normalization to ensure data consistency across the LeadGen OS. This includes trimming website URLs to their root domains and stripping taglines or secondary information from business names during both CSV import and bulk database updates.

---

### Change 1: URL Root Normalization — `backend/app/utils/csv_parser.py`

**Logic:** Updated `clean_website()` to use `urllib.parse.urlparse` to extract only the scheme and netloc.
- **Example:** `https://balanicustom.com/custom-suits-indianapolis` → `https://balanicustom.com/`
- **Impact:** Prevents redundant auditing of sub-pages and ensures all leads are tracked by their primary domain.

---

### Change 2: Business Name Cleaning — `backend/app/utils/csv_parser.py`

**Logic:** Added `clean_business_name()` to strip everything from the first ` - ` or ` | ` separator onwards.
- **Example:** `Bigmen Stout Men's Shop - Bigmen.com, Inc` → `Bigmen Stout Men's Shop`
- **Impact:** Produces cleaner personalization in emails by removing legalese or domain fragments from the business name.

---

### Change 3: Bulk Cleaning Endpoints — `backend/app/routers/leads.py`

Added two maintenance endpoints to fix existing data in the PostgreSQL database:

| Method | Path | Description |
|---|---|---|
| POST | `/api/leads/clean-urls` | Iterates all leads and normalizes `website` to root. |
| POST | `/api/leads/clean-names` | Iterates all leads and strips taglines from `business_name`. |

**Live Execution Results (April 22):**
- Cleaned **2,860** website URLs.
- Cleaned **234** business names.

## v4.3.0 — Email Mismatch Detection & Review System (April 20, 2026)

### Overview

Resolved a critical data-quality bug where the standalone scraper was capturing emails from third-party web-designers (e.g. `support@webador.com`) instead of the actual business email. Built a full automated scan engine and admin review UI to detect and correct these mismatches across all leads.

Triggered by: **Vertex Industries, S.L.** having `support@webador.com` (a web-design platform) in the DB while the real business email `info@vertexindustries.es` was discoverable on the website.

---

### Change 1: Lead Email Correction — Vertex Industries, S.L. (Targeted Fix)

**Root Cause:**
The standalone scraper captured the email from the website builder's support contact rather than the business's own domain-matched email.

**Steps taken (manual):**
1. Used the Email Review scan to detect the mismatch: DB = `support@webador.com`, website = `info@vertexindustries.es`
2. Updated lead email to `info@vertexindustries.es` in PostgreSQL
3. Reset `status` from `converted` → `emailed` and cleared `last_emailed_at`
4. Triggered fresh SEO audit + saved PDF to `samples/`
5. Sent Email #1 (trust-first) to the corrected address
6. All actions logged to `ActivityLog`

---

### Change 2: `EmailCorrection` ORM Model — `backend/app/models.py`

**New table:** `email_corrections`

| Column | Type | Notes |
|---|---|---|
| id | UUID PK | auto |
| lead_id | UUID FK | references leads(id) ON DELETE CASCADE |
| old_email | String(255) | email in DB at time of detection |
| new_email | String(255) | domain-matched email found on website |
| domain | String(255) | lead's website domain |

## v4.1.0 — Audit Engine Stability & Site Classifier v5 (April 19, 2026)

### Overview
Two major stability and quality improvements: (1) replaced the old "batch-then-sleep" audit runner with a semaphore-based rolling queue to prevent DB connection pool exhaustion under large lead volumes, and (2) completely rewrote `site_checker.py` with 4-variant URL resolution and SPA framework detection to eliminate false "UNREACHABLE" / "PARKED" classifications on valid live business websites.

---

### Fix 1: Semaphore-Based Batch Audit Runner — `audits.py` (CRITICAL)

**Problem:** Clicking "Audit All" on 400+ leads triggered all audits simultaneously via `asyncio.gather()`. This saturated the SQLAlchemy `QueuePool` (pool_size=20, max_overflow=40) and caused cascading `TimeoutError` failures — most audits would crash mid-run and be logged as failed.

**Additionally:** Clicking "Audit All" twice sent two concurrent batch jobs — doubling DB pressure and causing duplicate audit records.

**Root cause:**
1. `asyncio.gather(*[run_audit(id) for id in all_ids])` — unbounded concurrency, up to 400+ tasks at once
2. No mutex / flag to prevent a second batch from being triggered while one was already running

**Fix — Semaphore Rolling Queue:**
```python
_AUDIT_SEMAPHORE = asyncio.Semaphore(3)   # max 3 concurrent crawls
_BATCH_RUNNING   = False                  # double-trigger guard

async def run_batched(lead_ids):
    global _BATCH_RUNNING
    _BATCH_RUNNING = True
    try:
        async def guarded(lead_id):
            async with _AUDIT_SEMAPHORE:
                try:
                    await run_audit(lead_id)
                except Exception as e:
                    logger.error(f"Audit {lead_id} failed: {e}")
                    # error is ISOLATED — remaining audits continue
        await asyncio.gather(*[guarded(id) for id in lead_ids])
    finally:
        _BATCH_RUNNING = False
```

**Key improvements:**
- **Concurrency limit:** Only 3 audits run at a time (configurable 1–8) — DB pool stays well within limits
- **Error isolation:** `try/except` per-audit — one failure does NOT abort the whole batch
- **Double-trigger guard:** `_BATCH_RUNNING` global flag + HTTP `409 Conflict` response on duplicate trigger
- **New `/audits/stats` endpoint:** Returns `{batch_running: bool, total, pending, done, failed}` — used by frontend to correctly track batch state

**File changed:** `backend/app/routers/audits.py` — complete rewrite

---

### Fix 2: Micro-Session Refactor in Audit Engine — `audit_engine.py`

**Problem:** `run_audit()` held a single DB session open for the full duration of the audit — including the 45s network crawl, PDF generation, and image fetching. Under concurrent audits (even 3 at once), 3 sessions × 45s each = connections held 3× longer than necessary, accelerating pool exhaustion.

**Fix:** Refactored to **short-lived micro-sessions** — open a session, read/write, close immediately, then do I/O work without holding any connection:

```python
# Before — one session held open 30–60 seconds
async with get_session() as db:
    lead = await db.get(Lead, lead_id)
    await crawl(lead.website)       # 45s — session locked!
    await generate_pdf()            # 5s  — session locked!
    db.add(audit_record)
    await db.commit()

# After — micro-sessions
async with get_session() as db:
    lead = await db.get(Lead, lead_id)   # read, then immediately return connection

result = await crawl(lead.website)       # no session held during I/O
pdf    = await generate_pdf(result)      # no session held during I/O

async with get_session() as db:
    db.add(audit_record)                 # write-only, brief
    await db.commit()
```

**File changed:** `backend/app/engines/audit_engine.py`

### Fix 3: Site Classifier v5 — 4-Variant URL + SPA Detection — `site_checker.py`

Complete rewrite of the site classification engine to eliminate the two biggest causes of false "UNREACHABLE" / false "DEMO" classifications.

#### Sub-fix A: 4-Variant URL Testing (biggest false-UNREACHABLE fix)

**Problem:** The classifier tried only the single URL passed to it. If `https://example.com` timed out or failed DNS, the lead was flagged UNREACHABLE — even though `https://www.example.com` would have loaded fine. Many small business sites resolve *only* on the `www.` subdomain; a bare domain DNS failure is not equivalent to the site being dead.

**Fix:** New `_url_variants(url)` function builds all 4 variants and the classifier tries each one before giving up:
```
Order tried:
  1. https://www.domain.com   ← most business sites prefer www
  2. https://domain.com
  3. http://www.domain.com    ← for sites without SSL on bare domain
  4. http://domain.com        ← last resort
```
Rules:
- DNS failure on one variant → **try next** (not immediately UNREACHABLE)
- SSL error on https variants → try http variants automatically
- All 4 aiohttp variants fail → trigger `requests` sync fallback (also receives all 4 variants — previously only got the original URL)

**New function:** `_url_variants(url) → list[str]` — handles bare domains, www-prefixed, http/https inputs; deduplicates correctly.

#### Sub-fix B: SPA / JavaScript Framework Detection

**Problem:** `STRUCTURAL_THRESHOLD = 8000` — the structural analysis ran on any page under 8KB. React, Vue, Angular, Next.js, Svelte, Gatsby, Nuxt all deliver a tiny HTML "shell" like:
```html
<div id="root"></div>
<script src="/static/js/main.a1b2c3.js"></script>
```
This shell has: no `<nav>`, no contact info, 0 meaningful links. The structural check classified it as **DEMO ("Structurally dead")** — even though the site is fully live (rendered by JavaScript in the browser).

**Fix:** New `_has_js_framework(body)` function runs BEFORE structural check:
```python
def _has_js_framework(body_lower):
    # React / Next.js mount point
    if re.search(r'id=["\'](?:root|app|__next|__nuxt|svelte)["\']', body_lower): return True
    # Angular
    if re.search(r'<app-root|ng-version=', body_lower): return True
    # JS bundle file patterns (Next.js /_next/, Vite /assets/, CRA /static/js/)
    if re.search(r'/_next/static/|/static/js/main\.|/assets/index\.', body_lower): return True
    # Webpack/Rollup chunk file names
    if re.search(r'chunk\.[a-f0-9]{6,}\.js|bundle\.js', body_lower): return True
    # Multiple script tags + viewport meta = likely client-rendered SPA
    if len(re.findall(r'<script', body_lower)) >= 2 and re.search(r'<meta[^>]+viewport', body_lower): return True
    return False
```
If a JS framework is detected on a thin-HTML page → immediately returns `REAL`. Content is rendered by the browser, not present in the raw HTML.

#### Sub-fix C: Structural Threshold Reduced 8000 → 2000 chars

Clean, semantic HTML for a small-business site can easily be under 8KB. The structural check running on these produced false DEMO flags for legitimate businesses with minimal, well-written HTML pages.

**Fix:** `STRUCTURAL_THRESHOLD = 2000` — structural analysis now only fires on pages with under 2000 characters (truly skeleton-thin pages — less than one printed page of text).

#### Sub-fix D: Removed Ambiguous Signals

| Signal Removed | Was In | Why Removed |
|---|---|---|
| `"under construction"` | `DEMO_THIN` | Appears in real site footers: "New wing *under construction*" |
| `"coming soon"` | `DEMO_THIN` | Real sites use freely: "New products *coming soon*" |
| `"page not found"` | `DEMO_TITLE` | Moved to `SOFT_404_TITLE` only — a real 200-OK page can have this in a sub-heading |
| `"temporarily unavailable"` | `DEMO_TITLE` | Maintenance banners on live sites use this regularly |

## v1.1–v1.4 — Critical Bug Fixes

### v1.1 — Tailwind @apply Blank Screen Fix
**Bug:** Tailwind CSS `@apply` directives in `index.css` caused the entire React app to render blank.
**Root cause:** PostCSS plugin failed silently — no error, just blank white screen.
**Fix:** Ripped out ALL Tailwind `@apply` usage. Rewrote entire CSS system as plain vanilla CSS with custom properties.
**File changed:** `frontend/src/index.css` — complete rewrite.

### v1.2 — Lead Deletion Foreign Key Crash
**Bug:** Deleting a lead threw `IntegrityError` — "NOT NULL constraint on audit.lead_id".
**Root cause:** SQLAlchemy tried to `SET NULL` on the audit's `lead_id` column, but that column is `NOT NULL`. The `ON DELETE CASCADE` in SQL wasn't being respected because SQLAlchemy ORM was intercepting the delete.
**Fix:** Added `passive_deletes=True` to both `audit` and `activity_logs` relationships on the Lead model. This tells SQLAlchemy to let the database handle cascades.
**File changed:** `backend/app/models.py` — both relationship definitions.

### v1.3 — PDF Unicode Crash
**Bug:** PDF generation crashed with `UnicodeEncodeError` on non-Latin-1 characters (emojis, Hindi text, special quotes).
**Root cause:** FPDF2's default Helvetica font only supports Latin-1 (ISO-8859-1) encoding.
**Fix:** Created `_safe(text)` function that strips/replaces all non-Latin-1 characters before passing to FPDF2. Applied to every single `.cell()`, `.multi_cell()`, and `.write()` call.
**File changed:** `backend/app/engines/pdf_engine.py` — `_safe()` function + all output calls.

### v1.4 — Bulk Delete Bypass
**Bug:** Bulk deleting leads (multiple at once) used raw SQL `DELETE` which bypassed SQLAlchemy's ORM cascade events — audits survived as orphans.
**Root cause:** Bulk SQL `delete()` doesn't trigger ORM-level cascade.
**Fix:** Added **explicit** `DELETE FROM audits WHERE lead_id IN (ids)` before `DELETE FROM leads WHERE id IN (ids)` in the bulk delete endpoint.
**Files changed:** `backend/app/routers/leads.py` — bulk-delete endpoint.

## v2.6–v2.8 — April 2026 Optimization Sprint

### v2.6 — UTC Timezone Fix (CRITICAL BUG)

**Bug:** Activity log showed events as "6 hours ago" when they happened minutes ago.
**Root cause chain:**
1. PostgreSQL stores `TIMESTAMP` (naive, no timezone) — assumed UTC
2. SQLAlchemy returns naive `datetime` objects
3. Pydantic serializes as `"2026-04-04T13:30:27"` (no timezone indicator)
4. JavaScript `new Date("2026-04-04T13:30:27")` treats this as **local time** (IST = UTC+5:30)
5. `formatDistanceToNow()` calculates from local interpretation → ~5.5 hours off

**Fix — Backend (`schemas.py`):**
```python
def _as_utc(v: datetime) -> str:
    if v.tzinfo is None:
        v = v.replace(tzinfo=timezone.utc)
    return v.astimezone(timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ')

class UTCBase(BaseModel):
    model_config = {"from_attributes": True, "json_encoders": {datetime: _as_utc}}
```
All response models (`LeadResponse`, `AuditResponse`, `CampaignResponse`, `ActivityLogResponse`) now inherit `UTCBase`.

**Fix — Frontend (`ActivityLog.jsx`):**
```javascript
function parseUTC(str) {
  if (!str) return new Date()
  if (/[Z+]/.test(str.slice(-6))) return new Date(str)
  return new Date(str + 'Z')
}
```

if campaign.status != CampaignStatus.done:

## Architecture Decisions Log

| Decision | Why | Alternative Considered |
|---|---|---|
| psycopg over asyncpg | asyncpg binary fails on Python 3.14 | Wait for asyncpg fix (too slow) |
| Plain CSS over Tailwind | @apply caused blank screen, hard to debug | Tailwind without @apply (still risky) |
| Inline email templates | No template file loading issues, easy to edit | Jinja2 templates (adds dependency) |
| passive_deletes=True | Let DB handle CASCADE instead of ORM | Manual delete in every route (fragile) |
| UTCBase inheritance | One fix for all datetime serialization | Per-field custom serializers (tedious) |
| Inline split-panel over modal | Eliminated all clipping/viewport bugs | Fixed-position modal (still problematic) |
| 15s polling over WebSocket | Simpler, no new infrastructure needed | WebSocket (overkill for current scale) |
| No sleep after last email | Campaign completes instantly | Webhook/callback (more complex) |

## v2.9 — AI Name Extraction & Lead Editing

**Date:** April 4, 2026

### Feature: AI Business Name Extraction
**Why:** Scraped leads frequently have noisy names like:
`"ADM Engineering | Plastic Manufacturing Company in Pune | HDPE Crates"`
**Solution:** After auditing a REAL website, `extract_business_name()` visits the actual site:
1. Tries `og:site_name` meta tag (highest accuracy)
2. Tries JSON-LD `@type=Organization → name or legalName`
3. Tries `<title>` first segment (splits on `| - – :`)
**Stored as:** `audits.suggested_name` (new column in audits table)
**File:** `backend/app/engines/audit_engine.py`

### Feature: Lead Edit Modal
**Why:** Users needed to fix scraped names and update outdated contact info.
**Implementation:**
- ✏️ edit icon added to every lead row in the table
- Modal with fields: business_name, email, phone, website
- If `audit.suggested_name` differs from `lead.business_name` → shows purple AI banner
- "Use this name" → auto-fills the name field; "Dismiss" hides the banner
- ⚠️ tagline warning if name contains `|` or length > 60 chars
**Files:** `frontend/src/pages/Leads.jsx`, `backend/app/routers/leads.py` (PATCH /{id})

### Feature: Delete All Leads
**Why:** User needed a way to wipe the leads table and start fresh.
**Implementation:**
- Red "Delete All" button in Leads page header
- Two-step confirmation: first confirm(), then must type "DELETE" into an input
- Backend: `DELETE /api/leads/all` — explicitly deletes audits first, then leads
- **Safety note:** Bulk raw SQL bypasses ORM cascade — explicit audit DELETE is required
**Files:** `frontend/src/pages/Leads.jsx`, `backend/app/routers/leads.py`

### Bug Fixed: Audit All Pool Exhaustion
**Bug:** Clicking "Audit All" with 400+ leads caused all audits to fail with DB pool errors.
**Root cause:** All audits were launched simultaneously — 411 concurrent DB connections overwhelmed the default pool (pool_size=5, max_overflow=10).
**Fix:**
1. Changed `trigger-all` to batch audits: 10 at a time, 2-second delay between batches
2. Increased DB pool: `pool_size=20, max_overflow=40`
**Files:** `backend/app/routers/audits.py`, `backend/app/database.py`

### Bug Fixed: Route Shadowing on /audits/pdf/{id}
**Bug:** `GET /api/audits/pdf/{lead_id}` returned UUID parse error because `GET /api/audits/{lead_id}` was registered first and captured the literal string "pdf" as a UUID.
**Fix:** Moved `@router.get("/pdf/{lead_id}")` ABOVE `@router.get("/{lead_id}")` in `audits.py`.
**File:** `backend/app/routers/audits.py`

## v3.0 — Campaign Engine & Management (April 2026)

**Date:** April 4, 2026

### Feature: Campaign Pause / Resume
**Why:** Campaigns could not be stopped mid-send. Server restart or power cut meant lost progress.
**Models changed:**
- `CampaignStatus.paused` — new enum value
- `Campaign.pending_lead_ids` — JSON list of remaining lead IDs saved when paused
- `Campaign.paused_at` — timestamp the pause was triggered
- `Campaign.skipped_count` — count of 7-day skips
- `Campaign.failed_count` — count of SMTP failures
**Endpoints added:**
- `POST /campaigns/{id}/pause` — sets status="paused" (runner self-terminates after current send)
- `POST /campaigns/{id}/resume` — sets status="draft", launches new background task from `pending_lead_ids`
**Engine logic:**
- `run_campaign()` checks `campaign.status == "paused"` BEFORE every email send
- If paused: saves `pending_lead_ids = remaining_ids`, returns cleanly
**UI:** Pause button (yellow) when sending; Resume button (green) when paused
**Files:** `backend/app/models.py`, `backend/app/routers/campaigns.py`, `backend/app/engines/outreach_engine.py`, `frontend/src/pages/Campaigns.jsx`

### Feature: 7-Day Email Skip
**Why:** Sending to the same lead multiple times in a week risks spam flags.
**Implementation:**
- `Lead.last_emailed_at` (DateTime) added to leads table
- Updated after every successful send
- Runner checks before each send: `if emailed within 7 days → skip`
- Logs "skipped" row to `campaign_email_logs` with reason
**Files:** `backend/app/models.py`, `backend/app/engines/outreach_engine.py`

### Feature: Live Countdown Timer
**Why:** User needed to see exactly when the next email would go out.
**Implementation:**
- `Campaign.next_email_at` (DateTime) — set to `now + delay_seconds` BEFORE `asyncio.sleep()`
- Frontend `useCountdown(next_email_at)` hook — ticks every 1 second
- Displays: "🕐 Next in 6m 42s" counting down in real-time
- Polling reduced from 15s to 8s for better responsiveness
**Files:** `backend/app/engines/outreach_engine.py`, `frontend/src/pages/Campaigns.jsx`

### Feature: Per-Email Campaign Logs
**Why:** Full transparency on every send attempt.
**New model:** `CampaignEmailLog` (table: `campaign_email_logs`)
- Fields: campaign_id, lead_id, business_name, email, status (sent/failed/skipped), message, created_at
- Cascade: deleting campaign deletes all its logs
**Endpoint:** `GET /campaigns/{id}/logs?limit=100`
**UI:** Click ▶ chevron on campaign row to expand inline log table
- ✅ sent (green), ✗ failed (red), ⟳ skipped (yellow)
**Files:** `backend/app/models.py`, `backend/app/schemas.py`, `backend/app/routers/campaigns.py`, `backend/app/engines/outreach_engine.py`, `frontend/src/pages/Campaigns.jsx`
