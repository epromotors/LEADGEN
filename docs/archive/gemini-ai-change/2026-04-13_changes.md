# LeadGen OS Changes - April 13, 2026

This document records the changes made to the project today by Gemini AI, detailing the files affected and the reasons for the modifications.

### 1. Fixed "NO WEBSITE" Classification Bug
- **File Changed:** `backend/app/utils/site_checker.py`
- **What Changed:** Added a URL normalization check inside the `classify_site(url)` function. If an incoming URL does not start with `http://` or `https://` (e.g. `gautomobilemechanic.co.uk`), the system now automatically prepends `https://`.
- **Reason:** The `aiohttp` library requires explicit protocol schemes. Previously, naked URLs triggered an `InvalidUrlClientError`, which a generic exception handler was misclassifying as an `UNREACHABLE` site. This bug was causing live lead domains to skip the complete 19-point SEO audit entirely and improperly send out the "No Website/Offline" error email.

### 2. Batch Re-Audit of Failed Leads
- **File Changed:** None (One-time Database Script Execution in `backend`)
- **What Changed:** Designed and executed an asynchronous script using SQLAlchemy to query leads audited within the last 24 hours that had never received an email reply/send interaction. 
- **Result:** Successfully reverted **2,502 affected leads** back to `LeadStatus.new` and reset their corresponding audits to `AuditStatus.pending`.
- **Reason:** The user requested that recent records impacted by the aforementioned "NO WEBSITE" bug be safely re-queued to the audit engine so they could be properly analyzed and evaluated without erasing any older progression.

### 3. URL Deduplication & Database Cleanup
- **File Changed:** None (One-time Database Script Execution in `backend`)
- **What Changed:** Designed and executed a script targeting the central `Leads` table to locate duplicate website entries. The script stringently normalized all URLs globally across the database (stripping `http`, `www`, and slashes) and grouped them.
- **Result:** Evaluated URL groups system-wide and safely deleted **81 duplicate lead entries**. When deleting, the function retained whichever copy of the lead had the furthest status maturity (e.g. Emailed, Replied) and longest history, purging only redundant records.
- **Reason:** Ensuring that the database maintains pristine data hygiene. Redundant leads mapped to identical web domains waste computing resources during audits and artificially bloat email outreach statistics.

### 4. Business Name Tagline Cleanup
- **File Changed:** None (One-time Database Script Execution in `backend`)
- **What Changed:** Scanned 2,426 new and recently audited leads to parse out unnecessary taglines or SEO spam appended to business names. Any name containing a vertical pipeline symbol (`|`) or a spaced hyphen (` - `) was automatically cut to retain only the genuine business name before the delimiter.
- **Result:** Identified and permanently cleaned **247 business names** across the targeted dataset.
- **Reason:** The web frontend was displaying a yellow error flag parsing elongated or keyword-stuffed business names. This process stripped the clutter programmatically, ensuring clean text for email templates and resolving the interface warnings.
